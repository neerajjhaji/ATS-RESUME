Resume Tailor

A full-stack ATS optimization tool that scores a resume against any job description, pinpoints the exact gaps, and rewrites them line by line — powered by a three-model Google Gemini pipeline.

01

Architecture

Resume Tailor is a single Next.js application. The browser renders an interactive split-panel dashboard; all AI work and file parsing happen server-side in Node-runtime route handlers, so the Gemini key and heavy parsing libraries never reach the client.

Client (browser)

A React client component orchestrates state: inputs, applied edits, keyword injections, and the live editor. It talks to three API routes over fetch and renders results into the dashboard.

Server (Node runtime)

Route handlers extract text with pdf-parse/mammoth, then call Gemini through the official SDK with enforced JSON schemas. Errors are caught and returned as structured messages.

02

The dual-engine pipeline

Each task is routed to the model that fits its performance profile — fast flash models for extraction and short-form generation, the pro model for deep strategic reasoning. The three phases run in sequence, with results flowing from one to the next.

Phase 1 · Parse

Extract & normalize

gemini-3.6-flash

Raw text is pulled from the PDF/DOCX, then normalized into clean, single-column, ATS-parsable plain text. Falls back to raw extraction if the model call fails.

→
Phase 2 · Analyze

Deep ATS audit

gemini-3.1-pro

Scores the match, buckets matched vs. missing keywords, and emits verbatim-anchored, line-by-line rewrites — all under an enforced JSON schema.

→
Phase 3 · Generate

Cover letter

gemini-3.5-flash

Optionally drafts a tailored cover letter that leans on matched strengths and the gap analysis from Phase 2.

02b

Standalone ATS score

Separate from the job-specific pipeline, Resume Tailor can predict an ATS score from the resume alone — no job description and no target title required. It's a fast resume health check that grades general parsability and quality.

How it differs from the audit

The main audit scores fit to a specific role. The standalone score judges the resume on its own — formatting, quantified impact, action verbs, section completeness, keyword density, and length/contact hygiene — and returns a per-dimension breakdown plus general quick wins.

FieldMeaning
ats_scoreOverall readiness, 0–100
verdictPlain-language summary of resume health
breakdown[]Per-dimension { category, score, note }
quick_wins[]3–6 general, role-independent improvements
03

Model routing

Every call reads its model ID from one table in lib/gemini.ts. Change a value there and it propagates to every route.

ConstantModelResponsibility
FLASH_FASTgemini-3.6-flashFast parsing, PDF/DOCX extraction, keyword pre-matching, UI streaming.
PRO_STRATEGYgemini-3.1-proDeep ATS match scoring, gap detection, line-by-line rewrites.
FLASH_AUXgemini-3.5-flashCover letters, summary rewrites, interview-prep questions.
⚠ Verify before deploying

The model IDs above come from the project specification. Confirm your API key has access to them at ai.google.dev/gemini-api/docs/models, and edit the MODELS table in lib/gemini.ts if your account exposes different IDs.

04

API reference

Three Node-runtime route handlers. All return JSON; on failure they return { "error": string } with an appropriate status code.

EndpointMethodBodyReturns
/api/parsePOSTmultipart/form-data · file{ text, structured, source }
/api/analyzePOST{ resumeText, jobDescription, jobTitle }ATS audit object
/api/cover-letterPOST{ resumeText, jobDescription, jobTitle, analysis }{ cover_letter }
/api/ats-scorePOST{ resumeText } — no JD/titleATS readiness object

Example — request an ATS audit

const res = await fetch("/api/analyze", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ resumeText, jobDescription, jobTitle }),
});
const audit = await res.json(); // → typed AtsAudit
05

ATS audit schema

Phase 2 is constrained by config.responseSchema, so the model is forced to return exactly this shape — no fragile string parsing on the client.

{
  "match_score": 72,                    // integer 0–100
  "summary_critique": "…",             // alignment assessment
  "keywords": {
    "matched": ["REST APIs", "CI/CD"],
    "missing_hard_skills": ["Go"],
    "missing_tools": ["Kubernetes", "Terraform"],
    "missing_soft_skills": ["Stakeholder management"]
  },
  "actionable_changes": [
    {
      "section": "Work Experience - Acme Corp",
      "current_text": "Managed the backend.",     // verbatim, so it can be found
      "flaw_reason": "Lacks metrics and JD keywords.",
      "suggested_text": "Led a 4-service Go/Kubernetes backend serving 2M req/day…"
    }
  ]
}
Why verbatim current_text?

The editor applies a suggestion by finding current_text in the live resume and swapping it for suggested_text. Anchoring on the exact original snippet makes “Apply Edit” a deterministic, one-click replacement.

06

The interface

A two-column workspace. The left column captures inputs and, after analysis, becomes the audit dashboard. The right column is where you act on the findings and edit in place.

Left · Audit dashboard

  • ✓ Resume dropzone (PDF/DOCX) with a paste-text fallback
  • ✓ Target job title + job-description fields
  • ✓ Circular match-score gauge with a plain-language verdict
  • ✓ Keyword gap chips — click a missing keyword to inject it into Skills
  • ✓ Cover-letter generator card

Right · Rewrites & live editor

  • ✓ “Where & What to Change” feed with before/after diffs
  • ✓ One-click Apply Edit updates the resume instantly
  • ✓ Editable single-column, ATS-parsable resume (no multi-column tricks)
  • ✓ Export to ATS-clean PDF or Markdown
  • ✓ Reset to revert to the originally parsed resume

Score gauge — how to read it

0–49 · Weak match 50–74 · Needs work 75–100 · Strong match

Setup & run

Requires Node 18+. Get a Gemini key at aistudio.google.com/apikey.

# 1 · install dependencies
npm install

# 2 · configure the key (server-only, gitignored)
cp .env.example .env.local
# then edit .env.local:
GEMINI_API_KEY=your_gemini_api_key_here

# 3 · run
npm run dev        # http://localhost:3000
npm run build      # production build
npm run typecheck  # tsc --noEmit

09

Security model

  • ✓ The Gemini key lives only in .env.local (gitignored) and is read via process.env.GEMINI_API_KEY on the server.
  • ✓ No NEXT_PUBLIC_ prefix — the key is never bundled into client JavaScript.
  • ✓ No API-key input field in the UI, by design.
  • ✓ File parsing and all model calls run in Node-runtime routes, never in the browser.
